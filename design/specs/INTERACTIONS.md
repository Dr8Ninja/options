# Interaction and state contract

Use with [FRONTEND](../../docs/engineering/FRONTEND.md), [P05](../../docs/engineering/API.md), [components](COMPONENTS.md) and [journey manifest](../routes.json). API messages are mapped by code, never displayed by dumping backend error text. Prototype review states demonstrate layout only; the application must obtain real state from server DTOs.

## Global state rules

Initial content has a stable heading and context. Loading announces by 500ms, keeps confirmed public content where safe, and offers deliberate retry by 10s; no shimmer. Empty is a distinct 200 result with an explanation and useful action. Local invalid input is associated with its field and summarized near the form heading. Pending mutations disable only their own submit action, retain fields and expose “Saving…”; confirm success only after committed acknowledgment. Never turn an HTTP error into a success toast. Success remains inline, not only in a disappearing toast.

Offline writing stays in memory, visibly unsaved; offer select/copy and navigation warning. No offline synchronization/background retry queue. Refresh may lose unsaved writing and says so. Duplicate clicks reuse the operation's idempotency key while pending; a deliberate new attempt uses the correct new command. 412 or mismatched base requires comparison and explicit reapply; 409 content version resets catalog pagination without changing an enrolled denominator. A failed public load keeps safe existing text; safety withdrawal clears it, even on a failed background exporter.

Session recovery: 401 hides protected content/controls, retains unsaved in-tab work where safe, and presents same-origin sign-in return. Sign in as a different principal clears private memory before rendering; never attach previous-account drafts to the new owner. 403 stale CSRF obtains a fresh token but does not automatically retry the mutation. 403 role/MFA/recent-auth explains the needed capability without leaking a hidden object's title. Logout warns before clearing unsaved text and performs full navigation. Auth/API responses are no-store; back/forward restoration revalidates session before showing protected content.

429 shows a human-readable earliest retry time from Retry-After, keeps typed fields and permits deliberate retry only when eligible; no timer announcement each second. 500/503 gives safe message/reference and retry with bounded delay. Another owner's private resource is indistinguishable from not found. Publication/deadline changes revalidate on navigation/focus/every 30s visible; changing a lesson does not discard its separate unsaved note.

## Specific confirmation layouts

Note conflict: current saved text and timestamp/version, own unsaved text, “Keep editing mine”, “Use latest” only after warning about discard, and explicit “Save my resolved version” using freshly read ETag. No default merge or automatic overwrite. Three-way editorial/import diff adds base and proposed labels, semantic changed fields and affected approval summary; resolution creates a new draft based on current head.

Gate review: show answered/remaining counts, stable question links and a list of explicit skipped ordinals. “Submit final answers” is distinct from “Back to questions”. An unanswered item requires a checked confirmation that it scores zero. Published gate failure is not announced until the server returns immutable result. Disable repeated submit while pending; a network-lost success uses the same key/body and retrieves the committed result. Before submission, the browser never has solution/rubric keys to hide with CSS.

Privacy deletion: heading names account and permanent loss; explain immediate access revocation and retention; recent sign-in gate; visible typed confirmation; destructive final button and Cancel. The product confirmation DTO uses DELETE_MY_ACCOUNT; UI converts deliberate confirmation to that exact command, not client owner/role fields. Receipt is minimal after revocation; no unauthenticated status endpoint. A “Cancel pending email change” action is available until confirmation/expiry and preserves old login.

Publication: list every selected object/revision/visibility, reviewer and same-author facts, unavailable approvals, changed public routes, linked assessment/recheck impact and expected active release. Confirmation becomes available only after candidate checks. On race, preserve candidate and show “A newer release is active. Refresh and review the difference”; no force overwrite. Withdrawal confirmation has an independently written safe public reason; rollback always repeats active exclusions. Administrator role/access changes require reason and display session revocation, two-key activation/last-operator constraints and no private learner content.

## URL, focus and input details

Production query params use repeated values for a facet, OR within name / AND across names. UI labels may be friendly but wire values preserve exact canonical ranges. Serialize sorted stable keys/values for shareability; remove defaults where harmless, never silently translate unknown values. Form Apply pushes a new URL and resets pagination. Browser Back restores query/chips/sort and result position, not a second request with stale cursor. Content-generation mismatch clears cursor stack and announces a restart at the first page.

Default keyboard order is shell → page heading/context → primary reading/form content → side actions → footer. No positive tabindex. Production disclosure summaries use Enter/Space, not custom tree navigation. User-operated in-page anchors focus the target heading with tabindex=-1. Skip link focuses main. Menu disclosure closes with Escape and returns focus to Menu. Modal Escape cancels without changing records. Preserve focus while updating a status; move it only after navigation, submit result, explicit validation failure or closing a modal. Live regions announce one concise state change; do not reread the whole form.
