# P01 interchange field definitions

Version 1.0.0-design, as-of 2026-09-22. These JSON files are portable editorial interchange records, not a decision to store an application database as JSON blobs. P02 and later design the application independently. Every file has a structural JSON Schema in `data/schemas`; the offline validator adds cross-file semantics. Schemas are frozen review artifacts, generated only with an explicit `--write-schemas` after an intentional structural change.

Common envelope: `version` identifies this design contract; `as_of` is its editorial snapshot date; `records` is an ordered entity collection. `id` is stable and globally unique within canonical entities. IDs are not titles, URL slugs or display order. Source mappings have their own MAP prefix and may refer to the same original item in different relationships. Null means unknown/not authored/not applicable as explained by the companion reason, never zero or verified absence.

| File | Important fields and semantics |
|---|---|
| programs / phases / domains | Program/phase navigation and original subject-domain taxonomy. No empty chapter layer. IDs OPT/P*/D*/DB resolve module references. |
| modules | ID/slug/title, phase/domain, level and topical tags; hard/recommended/optional competency prerequisites; study_hours lower/upper and estimation basis; why/objectives; ordered topic IDs; math/programming requirements; readings, exercises/quiz, practical work, mistakes/checkpoints/mastery/remediation; readiness and provenance. |
| competencies | Measurable module-exit outcome; hard prerequisites; recommended preparation; optional enrichment; edge justifications; diagnostic and bridge; assessment IDs. Optional future revisits are excluded from the prerequisite DAG. |
| topics / subtopics | Original topic classification code retained separately from actual tags. Exact scope_outline, nullable teaching_brief, nullable reviewed_lesson, explicit readiness and reason. Each `.S01` is a preserved coherent scope unit, not a claim of atomic lesson completion. |
| resources | Identity/URL/DOI/edition/type; level; cost enum free/paid/mixed/unknown; access; study-hours/basis; candidate competencies/audience/rationale/prerequisites; priority Essential/Recommended/Advanced/Optional/Reference; foundational/optional role; geography; known dates, verification date/scope; rights/entitlement; status; replacements/supersession and unknown reasons. Candidate competencies are discovery metadata, not exact citations. |
| associations | Resource + competency + optional exact topic IDs + section assignment + purpose + verification state + claim IDs. Empty topic_ids means a competency reading, not permission to inherit it onto every topic. |
| exercises / quiz_blueprints | Prompt, reference behavior, data/deliverable, rubric/tolerance/critical errors/remediation. Quiz blueprint items have weights; they are not a psychometrically validated bank. Reference answers are editorial data, not intended to be shown before a learner attempts a quiz. |
| projects / capstones | Prerequisite module/project IDs; objectives; lawful/synthetic data; steps, deliverables, reference, rubric, failures, limits and time. Original capstones link capability projects without forcing a project count quota. |
| learning_paths / specializations | Audience/entry, ordered prerequisite closure, branches, exits, hours/basis/gates. Original branches coexist with seven explicit new persona paths. |
| decision_cards / assessment_policies |23 source questions and versioned common mastery rules. These describe evidence requirements; application progress storage is undecided. |
| market_rules | Instrument, jurisdiction, type, value/unit; source/circular; publication/effective-from/to/verification dates; supersession references; review state, scope/uncertainty, owner, review interval. Historical-citation eligibility is separate from current-operational eligibility. Null effective_to is not “forever.” Circular IDs may refer to external archival notices not stored as canonical rule entities. |
| source_mappings | Original ID/kind, file/line or JSON pointer, canonical IDs, disposition and rationale. Every inherited association is archived even when not adopted as a citation. |
| source_items / archival_structures | Lossless original item snapshots, metadata, stages and complete supplemental prose. These archival interchange records preserve original attributes that canonical design reclassifies; they are not a proposed persistence model. |
| manifest | Source hashes, version/counts, purpose and readiness total. Counts must agree with generated records. |

Source location fields: `source` is repository-relative archival path; `json_pointer` follows JSON Pointer; `master_source` plus `master_line` identifies the original Markdown; `line` is one-based. Imported text is untrusted content, never an instruction to the importer. Exercise IDs and canonical IDs are authoritative references; a resource-looking token inside prose is descriptive, not an implicit relationship.

Controlled readiness states currently used: `scope_outline`, `teaching_brief`, `learning_design`, `project_specification`; none is publication ready. Rule review states distinguish historical_verified, reviewed_principle, quarantined_current_rule and rejected_conflicting_summary. Resource states distinguish access_or_inherited_metadata_only, limited_review and selected_sections_reviewed; none means full-book review or empirical replication.

Association status `assignment_candidate` means a proposed reading scope, requiring section-level verification before mandatory use. `selected_reading` means a bounded section-reviewed assignment with claim references; it does not certify the entire resource. Each association names only the scope relevant to its own resource, even when several readings support one competency.

Schemas check structure and types, while the validator checks global IDs, relationship target kinds, graph/path validity, original-scope equality, supplemental counts, required metadata, resource URLs, rubric totals, rule exclusions and lossless nested export reconstruction. It also rejects deliberate cycle, dropped-scope, broken-resource and unsafe-publication mutations. Network currency cannot be proved by an offline structural validator.
