# Initial security design — P03

23 September 2026. This is a threat model and implementation contract, **not a security certification or test report**. Scope: [R1 product requirements](../product/PRODUCT_REQUIREMENTS.md), [architecture](ARCHITECTURE.md), [session decision](adr/004-browser-identity.md), [content ownership](adr/005-editorial-authority.md) and [hosting](adr/006-hosting-topology.md). P19 performs the release security/privacy review after implementation.

## Assets, actors and boundaries

Protect identity/session credentials, private learning records, authoritative scores, editorial integrity, protected answers, lawful source use and recoverable operations. Actors include anonymous visitors, malicious/legitimate learners, editors, publishers, administrators, compromised dependencies, external resource hosts, hosting/mail/storage processors and infrastructure operators. An editor is trusted to propose text, not to execute code or read everyone's notes. Administrative authority in the application does not make access to private learner text routine.

Untrusted browser → TLS ingress → private Next/Spring network → database crosses progressively narrower boundaries. Next receives private SSR data and the HttpOnly cookie at the server, so a compromised Next runtime is a session/data risk even without DB credentials. Spring is the sole business authorization/scoring authority. Database/migration/backup credentials have separate capabilities. External email/storage providers receive only the required data over TLS; operator-console access has independent MFA and audit. Internal service HTTP trusts the isolated hosting environment; it is not end-to-end encrypted. No production learner data is used for CI, public previews or demonstrations.

## Data classification and lifecycle

| Class | Examples | Allowed handling / lifetime |
|---|---|---|
| Public approved | Published lessons, approved map metadata, resource bibliographies, permitted historical rule records | Public DTO/HTML only after review; immutable public asset caching allowed; copyright/attribution still apply |
| Restricted editorial | Drafts, review notes, source archives, unreleased manifests, assessment keys and future forms | Authenticated role-specific API/operator export; no public Git/static assets/search; retain provenance with minimized actor identity |
| Private learner | Email/profile, notes, bookmarks, progress, attempts, dossier, private correction requests | Owner-scoped server queries/exports; active account lifetime, then deletion schedule; no public profiles or instructor browsing |
| Authentication secrets | Password hashes, session IDs, token secrets/digests, WebAuthn challenges, SMTP/API credentials | Never in telemetry/URLs except necessary one-time email link; secrets in protected environment store; no general admin read API |
| Sensitive operations | Security events, account deletion IDs, encrypted backups, infrastructure access | Least privilege, independent recovery access; bounded retention and restore controls |

Unverified accounts expire after seven days. Inactivity at 24 months starts the product's authorized notice and 30-day deletion process. Explicit account deletion immediately hides the account and revokes sessions; live erasure completes within seven days, backups within 35. Deleting an individual note removes it immediately from the live system; remaining encrypted backup copies age out within 35 days. Expired/revoked token secrets are purged within 24 hours. Security metadata is retained 90 days, sanitized operational logs 30, aggregate operational metrics 90, resolved issue reports 90 and minimal deletion ledger IDs 90. Content publication audit remains as provenance with minimized or pseudonymized personal identifiers. Export downloads expire after 24 hours; jobs complete within the product's 24-hour target. Retention applies to failed jobs, caches, temporary files, object versions and email-token outbox payloads too.

R1 does not collect date of birth, phone, financial balances, brokerage credentials, trades or advertising identifiers. Eligibility is a binary attestation under the pending U02 policy. Enforce privacy export/deletion even for suspended accounts through the documented operator route. Export includes only owner data and permitted attempted-question feedback, never unattempted answer keys, hashes or credentials. Break-glass access to private records is time-limited, purpose-recorded, least-scope and audited; routine editor/admin screens cannot use it.

## Browser and content controls

Use HSTS after HTTPS/domain validation, X-Content-Type-Options nosniff, frame-ancestors none, a restrictive Permissions-Policy and Referrer-Policy no-referrer on token/account pages (strict-origin-when-cross-origin acceptable for ordinary public references). CSP scripts use a per-response nonce and no unsafe-eval in production; restrict connect/img/font/form/base sources to the documented allowlist. A nonce is never cached or reused. KaTeX's generated style exception does not permit raw author HTML/styles. No third-party inline analytics or embedded login widget expands the policy. P19 tests the actual production build, including error pages, rather than assuming framework defaults meet it.

Token links use a configured origin and short single-use secret; token pages load no remote assets and do not log their query strings. A GET does not consume a reset token, protecting against email scanners; explicit CSRF-protected confirmation does. Return URLs are local allowlisted paths, never arbitrary hosts. One authenticated operator may occupy several roles but cannot skip review records or secret controls. Role changes, credential additions/removals, publications, withdrawals, recovery and break-glass operations generate audit events without storing raw confidential bodies.

## Operational security and incident response

Separate runtime, migration, read-only backup and operator credentials; no database superuser for requests. Use TLS-verifying database/mail/storage clients. Keep backups/exports private with short-lived authenticated downloads; do not expose guessable bucket URLs. Rotate secrets after exposure, revoke sessions/tokens, preserve minimal incident evidence and re-establish trusted builds. Audit infrastructure MFA and recovery custody before launch; no default account or emergency bypass secret in source.

For an incident: contain affected routes/accounts/credentials, record timeline and scope, preserve redacted evidence, assess data exposure, restore a verified clean version, reapply deletion/withdrawal rules, verify owner isolation, and communicate through the authorized operator process. Whether legal notification is required depends on the still-open operator/territory facts in U02; this design invents no legal conclusion or notification deadline. No automated public notices or external messages are sent by this assignment.

P19 must close or explicitly block every applicable critical/high finding; security exceptions cannot silently weaken P02. P21 must show timed recovery and log/backup lifecycle evidence. U01 coverage, U02 privacy/operator facts, U03 rights, U04 privileged recovery ownership and U05 email identity remain explicit release dependencies. The documentation validator cannot certify these controls are implemented.


## P10 implemented public reads

Only the explicit catalog/description/search/facet/route GET and HEAD routes are public; mutation methods on those resources return 405. Unimplemented private/admin routes remain default-denied for anonymous and authenticated staff callers. The public service ignores identity and uses repeatable read-only transactions, closed DTO projections and bound query values. No preview flag or unpublished filter is accepted.

Search and relationship filters are publication-derived. Draft bodies, new draft slugs, reserved never-public routes, raw import/source records, project reference/rubric keys, question forms/choices/answers and private records are not queried for public output. Public description projections for protected quizzes/exercises cannot start attempts or expose protected prompts. Generations advance on retirement, withdrawal and public rule/evidence safety changes. Rule deadlines are checked at request time and assembly is retried if a timed safety boundary passes.

All dynamic responses remain no-store; public reads allocate no session. Cursor MAC keys are database-local random bytes readable only by the runtime/migration authority, excluded from importer/export/public DTOs. Cursors are short-lived, bound to normalized filters/sort/limit/generation, and never authorize private data. The [P10 review](evidence/p10/REVIEW.md) records actual API, adversarial and scale checks; it does not replace P19 security/privacy review or P20 load testing.
