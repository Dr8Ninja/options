# P04 schema specification and data dictionary

P04 design contract, 23 September 2026; implemented under P08 on 25 September. [Overview](../DATABASE.md). Names below remain the normative design dictionary; [P08 implementation differences](IMPLEMENTATION.md) and the generated PostgreSQL audit describe executable details.

## Global column and constraint conventions

`id` means `bigint identity PK`; `u` means UUID with a unique constraint; plain `uuid` has only the explicitly listed composite uniqueness; `ts` means `timestamptz` stored/compared as an instant; `date` is a civil calendar date, never silently converted from a timestamp. UTC database/session defaults, explicit IANA zone for market-boundary interpretation. PostgreSQL [timestamp behavior](https://www.postgresql.org/docs/18/datatype-datetime.html) does not preserve an original input zone, so rules store it separately. `sN` = varchar(N); `textN` = text with `char_length <= N`; `n` = numeric(18,6); `pct` = numeric(5,2), 0–100. `?` alone marks nullable. All other fields are NOT NULL. Empty and null are different: reject blank IDs/names; unknown metadata uses null plus an explicit reason, not empty text or fabricated dates. Unicode lengths are code points at the API/database boundary; byte limits apply additionally to payloads.

Framework spring_session and spring_session_attributes are exceptions: use the exact pinned framework columns, without generic timestamp/version additions. All other standalone entities have `created_at ts DEFAULT transaction_timestamp()`; mutable rows additionally have `updated_at ts` and `lock_version bigint DEFAULT 0 CHECK >=0`. Pure joins use their owning revision timestamp and need no independent timestamps. Immutable rows have no generic updated_at. Columns omitted under these common conventions are not optional. All `→` references mean actual FK, default ON DELETE RESTRICT / ON UPDATE RESTRICT. Explicit account-owned CASCADE exceptions appear below. FK columns receive indexes when not covered by a PK/unique index or a deliberately documented low-volume scan.

`r` abbreviates a revision detail's `revision_id bigint PK`, `kind s32 CHECK = <its required kind>`, composite FK `(revision_id,kind) → catalog_revision(id,kind)`. The revision table has the required unique target keys. Kind strings use closed CHECK lists, not dynamically editable types. A deferred constraint trigger verifies each sealed revision has exactly its required typed detail (or no detail for PROGRAM/PHASE/DOMAIN/MODULE/TOPIC/SUBTOPIC/CAPSTONE/SPECIALIZATION). Deferrable FKs allow one transaction to assemble a valid aggregate. Runtime roles cannot alter sealed revision aggregates; P08 implements a trigger plus privileges, not a convention alone. Capstones/specializations need only common fields, sections and typed links; empty detail tables would add no constraint value.

The section allowlist is migration-owned and kind-specific: PROGRAM qualification; MODULE why_it_matters/objective/required_math/required_programming/reading_summary/practical_assignment/common_mistake/checkpoint/mastery_criterion/remediation/authoring_owner; TOPIC original_evidence_class/original_classification; SUBTOPIC granularity_note; COMPETENCY dependency_reason; PROJECT objective/data_plan/step/deliverables/reference/failure_case/limitations/noncoding_route/critical_failure; PATH audience/entry/exit_statement/milestone/assessment_gate_summary; POLICY critical_error/evidence/retry/calibration/state_label; EXERCISE critical_error; SPECIALIZATION original_module_scope/depth; CAPSTONE original_brief. ### Additional relational constraints needed for the shorthand above

`enrollment` includes `path_object_id bigint NOT NULL`, FK(path_revision_id,path_object_id)→catalog_revision(id,object_id), kind PATH; partial U(account_id,path_object_id) where state IN (CURRENT,COMPLETED,BLOCKED). A changed course creates a new enrollment after marking old SUPERSEDED in the same transaction; old `previous_enrollment_id` must have the same owner/path; composite same-owner FK uses ON DELETE SET NULL(previous_enrollment_id) so erasure never nulls owner identity. `quiz_attempt` adds U(id,account_id), U(id,form_id). `attempt_answer` adds U(attempt_id,item_ordinal,question_revision_id). `project_work` adds U(id,account_id). `mastery_evidence` adds U(id,account_id); all cross-owner source links use these composite keys, not a bare ID alone. `rubric_revision_id` is constrained to the actual quiz/project version used, with a deferred consistency trigger.

`quiz_form.exposure_group` and `form_exposure.exposure_group` both FK to `assessment_exposure_group`. This registry provides a real FK even when several cosmetically revised forms share one exposure group. Significant new items need a new reviewed group. Abandoned attempts retain exposure; deleting an attempt individually is not an R1 API capability. Account deletion cascades all exposure/attempt data. A new group alone is insufficient: publication checks question overlap and requires an assessment review explaining equivalent difficulty and genuine transfer.

Default account cascades in this section are **privacy erasure only**, never content import/retirement. Same-owner FKs prevent forged references even if a service misses a check. Public content and all sealed assessment definitions remain RESTRICT-protected. The specification's nullable fields and FK exceptions are exhaustive design decisions; any additional persistence field added in P08 needs a documented purpose and privacy review.

Submitted answer/result immutability forbids normal updates and deletion; authorized owner erasure still cascades through these rows. P08 must ensure immutability triggers do not accidentally block the privacy worker. Ordinary importer/editor roles have no delete or update rights to owned assessment records. Retained source notices are immutable editions; an unresolved prior circular gets its exact identifier and unknown locator reason, never the newer circular’s URL passed off as its own.
