## Lossless details and mapping safeguards

- Source `module.program_id/phase_id` and parent arrays must agree on the imported home placement. Conflicting copies reject; they are not two independent truth columns. Once application programs reuse a module, export application memberships explicitly; a legacy single-home export retains its original home plus an extension manifest for additional placements, never silently drops reuse.
- `prerequisites` arrays and `hard_edge_justifications` merge by exact required ID. Preserve explanation and ordinal; no duplicate FK edges and no source prerequisite discarded as a “duplicate” without matching semantics. The application validates its resolved graph as well as the source graph.
- Tags are semantically sets in queries. The original artifact preserves any original tag array order; application interchange exports deterministic sorted tags with declared normalization version. Original byte export remains available separately. Ordered pedagogy, modules/topics, rubric steps and reading targets retain explicit ordinal. P09 round-trip comparisons must distinguish declared set normalization from ordered arrays and report it, not silently normalize arbitrary arrays.
- A date such as `2024-06` remains a month-precision string. Numeric end dates are not guessed; null means unknown with reason. Imported check dates are verification claims from the source, not new checks performed during ingestion. Rule source bound conventions require review before creating a normalized effective interval or certification.
- Assignment claim references load the cited records in `research/registers/claims.json`: class/claim/status/limits/date are typed searchable metadata; exact review scope, resource IDs, publication-readiness reason and next action remain in its hash-verified source artifact. Public assignment evidence shows the bounded claim/scope; it cannot show “fully reviewed” from a transport status. If a referenced claim is absent, reject the assignment package rather than store a dangling string.
- Inventory domain selectors map verbatim to provenance_anchor.locator_label; they are legitimate selectors, not missing JSON pointers or fabricated line numbers.
- Parent section fields are ordered prose, not unstructured substitutes for FK relationships. There are no operational topic/prerequisite/resource ID arrays in JSON columns. Unknown new fields fail import until mapped or consciously archived by a reviewed schema version.

## New R1 and account data

New R1 entities have P02/P17 provenance and new registered external IDs: courseR1-FND, gatesR1-G1–G6, diagnostic, dossierR1-CASE-01, authored exercise variants, questions and form groups. Existing P02 named IDs are preserved verbatim as reserved additions. They reuse the exact selected topic identities. Four-item diagnostic routing uses path_revision's diagnostic reference and question/remediation topic links; six gate requirements are separate. Seventy source blueprints are not relabeled as these six gates.

Users/roles/sessions; enrollment/progress/notes/bookmarks; submitted responses/results; editorial workflow/audit/import jobs; current rule certifications; privacy/recovery state have **no source seed pretending they exist**. P08 creates representation/constraints, P09 imports authorized content, and later prompts create actual user-owned records. No production learner, admin password, score, review approval or current rule certification is seeded from P01.

Chapters are consciously absent because no source requires that extra level; ratings/moderation remain FUT-01 with no R1 tables. Neither omission erases original source content or a product requirement. P09's acceptance tests must compare every collection's IDs/relationships and the supplemental artifact manifest before it is allowed to apply a package.
