# REST API and authorization contract — P05

Contract 1.0.2, 27 September 2026. **P10 implements the public catalog, description, route, facet and search reads; P07 implements CSRF.** Identity, learner writes, assessment execution and editorial HTTP workflows remain later stages. P09 imports are drafts; the persistent local catalog has no approved publication. P04's offline gate passed on entry. Canonical source is `1.0.0-design`; existing outlines and exercise designs are not reviewed public lessons. This contract implements [P02 requirements](../product/PRODUCT_REQUIREMENTS.md), [P03 identity](adr/004-browser-identity.md) and [P04 lifecycle](database/LIFECYCLE.md).

The normative wire definition is [OpenAPI 3.1.1 JSON](openapi/openapi.json). Read it with the exhaustive [operation authorization matrix](api/AUTHORIZATION_MATRIX.md), [request examples](api/REQUEST_EXAMPLES.md), [contract-test plan](api/CONTRACT_TEST_PLAN.md), [P08 persistence clarifications](api/PERSISTENCE_CLARIFICATIONS.md) and [review evidence](evidence/p05-review.md). OpenAPI defines paths, DTO fields, limits, headers and policy identifiers; this document defines cross-field and transactional rules. Neither silently overrides the other: disagreement is a contract defect. Generate frontend types from this file in P07; do not reverse-generate the initial contract from JPA entities.

## Scope, identity and compatibility

All routes, including identity, live under `/api/v1`. This deliberately replaces P03's illustrative `/api/auth/csrf` with `/api/v1/auth/csrf`; no unversioned alias is needed before implementation. Public reads are programs, phases, modules, topics, independently addressable subtopics, resources, paths, projects, capstone briefs, exercise/quiz descriptions, route resolution, discovery facets and search. Parent detail embeds bounded ordered references; there is no recursive entire-catalog expansion. The topic response supplies its subtopic/exercise links. Competencies and assignments appear within their consuming DTOs; there is no CRUD route for every table. Blueprint IDs such as QZ-M01 do not identify executable quizzes.

No chapter, resource-rating, moderation, live trading, uploaded project/code, arbitrary code execution, public learner profile or another learner's attempts endpoint exists. Ratings stay FUT-01; chapter hierarchy requires a reviewed future change. Project work is available only for the authored R1 dossier. PR01–PR12 are browsable specifications, not hosted submission workflows. Full paths are map-only until their entire required closure is publishable. R1-FND is the separate 36-topic, six-gate, one-dossier course defined in P02.

Canonical IDs are case-sensitive, permanent and URL-encoded as one segment: OPT, P0, M01, M01.01, M01.01.S01, R01, PATH-BEGINNER, PR01, EX-M01-C. Preserve gaps R13–R15. Newly authored identities use a registered kind prefix plus UUID; the kind registry is migration-owned. Never reuse an ID or old slug. Private resources use random UUIDs; sequential database keys never cross the wire. `contentVersion.asOf` is the stable commit instant of that generation, not the request clock. Before any approved publication exists, public catalog/status requests return 503 TEMPORARILY_UNAVAILABLE; bootstrap publication starts with expectedPublicationId=null/expectedGeneration="0". A `revision` is an opaque `rev-…` token mapped to an immutable object revision, not a JPA ID. `publicationId` is opaque `pub-…`; generation is a decimal string to avoid JavaScript integer loss. Internal lock versions become quoted, strong ETags scoped to one representation.

URLs for the website are separate from API IDs. `GET /routes?path=/modules/financial-arithmetic-and-economic-purpose` returns the stable identity/current route. A renamed route returns `status=RENAMED`; Next issues a 308 to the returned same-origin canonical path. API ID lookups never redirect to external resource URLs. Retired public identities return 409 `CONTENT_RETIRED` on detail, and resolve through `/routes` with safe successor IDs; unknown and never-public objects return identical 404. Safety withdrawal returns 409 `CONTENT_WITHDRAWN` only for previously public identities with an approved public message. Search excludes both. Never expose a draft's existence by its different error.

API major version, contract document version, interchange schema, renderer format, content revision and publication generation are distinct. `/api/v1` changes may add optional response fields or new operations; clients ignore unknown response fields. Required inputs, meanings, units, enum sets, defaults, filters, scoring, error codes and removal/renaming need compatibility review; breaking changes use `/api/v2` with a documented migration window. Unknown request fields and unsupported enum/filter/sort values are rejected. Canonical schema upgrades have their own importer migration; no automatic API-major change. Client contract tests pin this artifact's hash. An OpenAPI library upgrade cannot silently change these semantics.

## Representations and validation

JSON is UTF-8 and camelCase. Every response is a DTO projection with explicitly selected fields. Public DTOs contain only approved map/lesson information, never canonical raw records, JPA relationships, actor emails, reviewer findings, protected sections, quiz keys or restricted source prose. Admin `EditorialBody` is an explicit editing/interchange projection with a closed kind, typed canonical record or authored definition, sections and ordered typed links. `canonicalRecord.id` must equal body/path ID and its collection must match kind; incompatible payload combinations fail 422. Canonical record validation is necessary but not a publication approval. DTO-to-service commands are mapped explicitly; never bind to persistent entities.

Public metadata includes honest readiness, MAP/LESSON visibility, summary, difficulty/priority source labels, tags, duration with basis, revision and content version. `lessonMarkdown=null` for MAP, always; metadata may be approved while lesson work is incomplete. Planned exercises return `practiceAvailable=false` and `prompt=null`; initial P01 prompts sometimes embed answers, so they cannot be copied into runnable public exercise DTOs. Public project criteria contain broad objectives only; numeric reference behaviors and solution-bearing rubric details are protected. Public quiz DTO contains purpose, item count and general pass policy, **no questions, choices, form IDs, answer key or detailed scoring rubric**. Assigned questions appear only in an owner's active attempt. Critical-check labels, response units and rounding instructions may be shown without revealing expected values.

Object bodies reject unknown properties, including `ownerId`, `userId`, `accountId`, `roles`, `score`, `passed`, `mastery`, `publicationState` and internal version fields unless explicitly part of that operation's DTO. The sole role-changing input is the audited admin role command; registration/profile/import/assessment never accepts role or ownership assignment. Response-only identifiers never determine the current principal. Editor authorship/reviewer identity and same-author flags are derived by the server.

Lengths count Unicode code points. Trim identifiers, email and search edges, never passwords, notes or answers. Email identity trims and casefolds, without provider-specific dot/plus removal. Passwords accept 15–128 code points, spaces/paste and the P03 blocklist; login accepts up to 128 so invalid old/short input yields a generic login failure. Plain text notes cap at 10,000, issue text 2,000, and total dossier text across fields at 20,000. JSON duplicate keys, invalid UTF-8, malformed dates, nonfinite numbers, unknown fields or coercions (e.g. string boolean) are invalid. Generic JSON body maximum 1 MiB; admin revision/publication 10 MiB; WebAuthn 64 KiB aggregate; import ZIP 100 MiB compressed **and expanded**, each archived record ≤1 MiB. Reject compression bombs, traversal, symlinks and excessive nesting (>32); gateway and application enforce limits.

UTC timestamps use RFC 3339 with `Z`; calendar dates keep source precision. A resource's `publicationDate=2024-06` plus MONTH does not invent a day. Unknown values use null plus contextual explanation; they do not become zero, free, never-expiring or verified. Hours min/max are both null or both present with 0≤min≤max and a basis. Monetary/numeric learner answers are decimal strings, up to 18 integer and 12 fractional digits, no exponent, NaN or Infinity. Parse as BigDecimal; do not score binary floating point. Exact field units must match the pinned question, with only authored reviewed conversions permitted. Request validation gives an error rather than awarding zero for a malformed number.

Arrays are ordered where instructional order matters. Assignment topic sets are exact reviewed/candidate associations; module-inherited readings do not become individually verified topic assignments. Reference arrays cap at the schema bounds; a proposed revision exceeding a bound fails publication and needs a deliberate contract revision, never silent truncation. Unavailable referenced prerequisites retain safe approved identity/title and `availability=UNAVAILABLE`; a draft-only target has no public reference/title. Public lesson output uses restricted Markdown and P03 sanitization, not MDX or raw HTML.

## Listing, filters and search

Ordinary collection defaults: `limit=20`, valid 1–50; cursor optional on first page. Keyset cursor is opaque, authenticated against modification, ≤2,048 characters, expires after 30 minutes. It binds API schema, normalized filters, sort, limit, publication generation, last ordering tuple and, for private lists, principal plus a first-page creation watermark. Changing any bound input gives 400 `INVALID_CURSOR`; generation change gives 409 `CONTENT_VERSION_CHANGED`. Private cursors exclude subsequently created records, but updates/deletions can change the visible values; there is no promise of a historical private snapshot. Resuming an expired cursor gives 409 `CURSOR_EXPIRED`; restart from page one. Cursor is not an authorization credential. Every page rechecks ownership/public eligibility.

Collections return `items`, `limit`, `nextCursor` (null at end), plus contentVersion for public lists. Empty result is 200 with an empty array; never 404. No unbounded `size`, `include`, `expand`, arbitrary field sort or query DSL. Unknown/repeated scalar query names fail 400. Each multivalue filter accepts repeated query parameters (not comma splitting), at most ten distinct values, OR within a name and AND across names; duplicates normalize away. Unsupported filters on a route fail 400. Known but unmatched values give zero matches, unknown taxonomy values/IDs give 422 `INVALID_FILTER_VALUE`, with draft/unknown IDs indistinguishable. Facet values/counts use the exact same full intersection as results (no hidden self-excluding facet rule), with empty counts omitted. `/discovery-facets` defaults `entity=resources`, `q` applies only to search; max 100 values per facet, deterministically count descending then binary value ascending. No counts from hidden drafts, archives or protected keys.

| Endpoint | Supported filters | Default/order options |
|---|---|---|
| programs | none | title; -title; duration |
| phases | program | title; -title; duration |
| modules | program, phase, difficulty, tag, path | title; -title; duration |
| topics | module, phase, difficulty, priority, tag, path | title; -title; duration |
| resources | resourceType, difficulty, cost, priority, topic, tag, phase, source, path, geography, verificationStatus, readiness, visibility | priority (default); title; -title; duration; -verified |
| paths | difficulty, tag | title; -title; duration |
| projects / capstones | difficulty, topic, tag, path | title; -title; duration |
| search | kind, difficulty, resourceType, cost, priority, topic, tag, phase, module, source, path, geography, verificationStatus, readiness, visibility | relevance; title; -title; duration; priority; -verified |
| private/admin lists | only parameters declared in OpenAPI | created; -created (drafts title; -title) |

`difficulty`, `priority`, `resourceType` and `source` use exact source values returned by facets, preserving P04's canonical scalar labels. Thus `difficulty=Beginner` does **not** include `Beginner–Advanced`; clients may explicitly select both. No undocumented bucketing: priorities include the canonical Useful/Very Important/Specialized as well as Essential/Recommended/Advanced/Optional/Reference. `source` means exact author/organization label (e.g. OCC), not arbitrary URL host or archived source-file ID. Tags are exact stored tags. Cost has free/mixed/paid/unknown; unknown is excluded by free. Case-sensitive matching follows canonical labels. Geography filtering uses the exact canonical descriptive label returned by facets, never an inferred country taxonomy. verificationStatus uses the canonical resource review label; readiness uses content readiness, and visibility=LESSON implements Ready to learn. Module is an explicit membership filter in search. These P06 corrections fulfill P02 REQ-10/11.

`phase` resolves membership in the active manifest. `path` includes the selected course's exact topics or the full path's ordered modules/topics; optional branches are excluded unless explicitly in required membership. Resource topic/phase/path filters follow exact topic assignments; a module-only competency association cannot infer an exact topic match. Project path filters use explicit project membership, topic filters explicit reviewed topic links. Search filters on type-specific fields exclude kinds lacking the field; `cost=free` therefore restricts to resources. Topic/tag relationships never recurse through unrelated recommendations. Path definitions with planned members are inspectable; filtering does not make those lessons runnable.

Priority sort uses Essential, Very Important, Recommended, Useful, Advanced, Specialized, Optional, Reference, then unknown, with normalized title/ID ties. `-verified` sorts substantive verification date descending, unknown last, normalized title/ID ties; it never uses link-check time. These sorts apply to resources and search; nonresource results have unknown verification date. Title sort uses Unicode NFC then casefold, PostgreSQL binary/C collation, stable semantic ID ascending as tie-breaker. `-title` reverses only the normalized title, ID still ascending. Duration is hours.min ascending, unknown last, ID ascending. Parent references follow ordinal then ID; source ordinal is not inferred from a title sort. Private lists sort created_at and public UUID, both ascending for created and both descending for -created. All predicates precede ranking, count and pagination.

Search uses English `websearch_to_tsquery` over approved title (weight A), author (B), tags (C), summary/scope outline (D), never protected text, private writing or full raw lesson/exercise bodies. Fixed `ts_rank_cd` weights A=1.0, B=0.4, C=0.2, D=0.1, normalization=32. Candidate union includes casefolded exact semantic-ID and title matches even if tokenizer produces no token; deduplicate by stable ID. Order relevance by exact ID first, exact full title second, other text rank descending, normalized title ascending, ID ascending. Tied results are deterministic within a generation. No fuzzy typo expansion, popularity signal, paid boost or search cluster in R1. Match labels are EXACT_ID, EXACT_TITLE or TEXT; return a plain text snippet ≤400 characters from approved fields, no HTML highlights. PostgreSQL parameter binding applies to query and filters; sort maps to server-owned expressions.

Search `q` trims whitespace, max 200 characters; empty or absent is browse ordered by title even with default relevance. Punctuation-only input yields exact-ID/title candidates or empty results, not all results or a syntax error. English quoted phrases, OR and minus exclusion use PostgreSQL web search semantics; AND is implicit. Search uses bounded offset `page=0..99`, limit 1..50, with `page*limit≤4950`; page beyond result count returns empty items/hasMore=false and the filtered total. Page >0 requires the first response generation. Changed/missing generation returns 409/400 respectively. No snapshot retrieval by old publication is public. Filters and query are URL-shareable; do not persist raw queries in logs.

## HTTP, errors, retries and concurrency

Success is 200 for reads and replace/upsert operations, 201 for creates, 202 for accepted jobs/generic identity requests, 204 for deletes/logout. A body is absent on 204. Create/status operations with returned IDs supply Location (same-origin path); generic signup/reset acknowledgment does not. Validation failure never changes durable state. GET is business-read-only; CSRF GET may allocate its security pre-session, and reads may update session access metadata. HEAD returns the GET status/headers without body or learner mutation. Unsupported methods return 405 with Allow; unknown media types 415. No JSONP. Ordinary JSON success uses application/json; every API error uses application/problem+json. Gateway-generated API errors must use the same sanitized envelope.

Each error contains `type` (stable `urn:otr:problem:CODE`), `title`, numeric HTTP `status`, stable `code`, safe `message`, `fieldErrors` (possibly empty), UTC `timestamp` and server-generated UUID `requestId`, also in X-Request-ID. Optional currentVersion is supplied only after authorized resource lookup. `fieldErrors[].field` is a JSON Pointer or query/header name; never echo passwords, tokens, answers, notes, raw SQL or rejected values. No stack traces, class names, internal paths, constraint names or exception text in production. Clients localize by code and field, not message matching. Logs record code, route template and correlation only; the ingress must redact query strings on sensitive routes.

| Status | Codes and observable behavior |
|---|---|
| 400 | MALFORMED_REQUEST, INVALID_QUERY, INVALID_CURSOR; invalid JSON/syntax/encoding or query structure |
| 401 | AUTHENTICATION_REQUIRED, INVALID_CREDENTIALS; absent/expired/revoked session or generic bad login; no redirect to HTML |
| 403 | EMAIL_VERIFICATION_REQUIRED, FORBIDDEN, MFA_REQUIRED, RECENT_AUTH_REQUIRED, CSRF_INVALID, ORIGIN_REJECTED; known caller lacks capability/security prerequisite |
| 404 | NOT_FOUND; nonexistent or another owner's record, never-public object, inaccessible revision; identical bodies apart from timestamp/requestId |
| 409 | CONTENT_RETIRED, CONTENT_WITHDRAWN, CONTENT_VERSION_CHANGED, CURSOR_EXPIRED, ENROLLMENT_UNAVAILABLE, PREREQUISITE_REQUIRED, ATTEMPT_FINALIZED, ATTEMPT_FROZEN, FEEDBACK_NOT_AVAILABLE, FRESH_FORMS_EXHAUSTED, REMEDIATION_REQUIRED, IDEMPOTENCY_KEY_REUSED, IMPORT_CONFLICT, PACKAGE_ID_REUSED, REVIEW_REQUIRED, PUBLICATION_CONFLICT, EXPORT_NOT_READY; valid shape but incompatible state |
| 412 | VERSION_MISMATCH; stale If-Match or failed If-None-Match creation; authorized client can GET current state/diff, then explicitly reapply |
| 413 / 415 | PAYLOAD_TOO_LARGE / UNSUPPORTED_MEDIA_TYPE; no partial processing |
| 422 | VALIDATION_FAILED, INVALID_FILTER_VALUE, TOKEN_INVALID, ANSWER_INVALID, GRAPH_INVALID, SCHEMA_UNSUPPORTED; syntactically valid but invalid values/relationships |
| 428 | PRECONDITION_REQUIRED; required conditional version header missing |
| 429 | RATE_LIMITED; Retry-After integer seconds plus retryAfterSeconds; no account-existence details |
| 500 / 503 | INTERNAL_ERROR / TEMPORARILY_UNAVAILABLE; safe correlation; 503 Retry-After, including failure to stabilize publication after one read retry |

Ingress byte/rate checks precede expensive parsing; unsafe origin/CSRF filters may return 403 before identity; otherwise authenticate, enforce role/factors, owner-query (404), then compare version and validate domain state. This intentionally prevents attackers learning another owner's version. Generic register/verification-request/reset-request responses are the same 202 whether unknown, already registered or delivery intent was accepted; known/unknown addresses have equivalent throttling and bounded timing. Operational mail failures enter the private queue; broad service inability to accept requests returns the same 503 for every address. Used/expired/replaced verification/reset/email-change token is 422 TOKEN_INVALID with one generic message, never which condition applied. A reset never logs in automatically.

Bookmarks and notes target MODULE, TOPIC or RESOURCE only. Creation requires an approved active public target; existing entries survive retirement and list a safe tombstone. Notes on retained identities remain owner-editable/deletable after retirement; public withdrawal never discloses withdrawn lesson text through these DTOs. PUT note/progress/practice/draft requires exactly one of If-None-Match: * for creation or If-Match for replacement. Missing is 428, both supplied 400. Responses include the next ETag and complete saved value; explicit deletion of a missing owned note is 204, but stale deletion of an existing note is 412. Natural bookmark membership uses PUT/DELETE by object ID without version; repeated save retains original savedAt and repeated delete is 204. Other conditional mutations use If-Match from their GET; publication rollback uses the content-version ETag. BaseRevision in an editorial payload must agree with current head/ETag; a stale semantic base is 409 IMPORT_CONFLICT for imports, 412 VERSION_MISMATCH for direct editing. Conflict response carries no private diff; the authorized draft diff endpoint returns base/current/proposed snapshots. Notes retrieve only their own current value, no server history.

Every operation marked idempotency=required in OpenAPI requires a UUID Idempotency-Key. Scope receipts by principal (or pre-session if ever used there), method and route; canonical JSON digest includes all submitted fields/answers, independent of object key order but preserving arrays and decimal strings. ZIP uses exact bytes/hash. Same key/body returns original committed status and result identity with its currently authorized safe representation (immutable scores unchanged; mutable workflow status may have advanced); different body is 409 IDEMPOTENCY_KEY_REUSED. Check replay **after current identity/role/owner authorization but before stale precondition rejection**; otherwise a lost success response cannot be recovered. Content/feedback withdrawal policy still applies to a replay: return ATTEMPT_FROZEN/CONTENT_WITHDRAWN without removed text. Use a bounded receipt cache for 24 hours; lasting domain uniqueness for attempt creation/submission, active enrollment, issue/request IDs and import hashes still prevents duplicate durable effects after that window. An identical terminal attempt submission returns its existing result even with a new key; changed terminal answers return 409 ATTEMPT_FINALIZED. Reusing an attempt start key can never allocate a second form. P08 must implement durable receipts as justified infrastructure, not a learner analytics table.

Return created status 201 even when resuming the existing attempt/enrollment/draft project for a retried creation; same Location identifies the original. No automatically duplicated resource on a network timeout. Server retries serialization/deadlock transactions at most three times with same key; retry exhaustion is 503. Clients retain unsaved text in memory, display save failure, refetch CSRF after security changes and ask for deliberate retry; do not automatically replay an unsafe operation after 401/403/412. Logout clears private client state; private data never persists in a service worker or browser cache.

Initial rate budgets (token bucket with the stated full-window burst unless otherwise specified): public read 120/min/source, search/facets 60/min/source; anonymous CSRF 30/15min/source; transient evaluation 30/min/source; learner saves 120/min/account, attempt starts 10/hour/account, submissions 30/hour/account; editorial writes 60/min/actor; imports 5/hour/actor and one validating job/actor; exports two/day/account. Identity failure threshold: ten failures/address/15min produces a 15min block; additional 30 failed logins/source/15min. Registration/reset/resend share five/hour/address and 20/hour/source (unknown addresses counted too). WebAuthn options/finish share 30/15min/account. Global ingress 100 req/s burst for 30s, expensive password hashes max four concurrent with bounded queue 20; overloaded work is 503. Shared stores enforce across nodes; trust only normalized ingress IP. These are testable starting policy, tunable after P19/P20 with documented review; Retry-After is the longest applicable wait. No permanent account lock or silently discarded successful mutation.

## Roles, owner boundaries, sessions and SSR

Every operation has an `x-authorization` policy in OpenAPI and a row in the [matrix](api/AUTHORIZATION_MATRIX.md). These are service-layer checks as well as route rules. The hierarchy is **not** ADMIN > publisher > editor > learner. One account can hold several independent roles. Private records always require the requesting owner, including for staff.

| Policy | Anonymous | Unverified password session | Active verified learner | Editor | Reviewer/publisher | Admin | Ownership/additional rule |
|---|---|---|---|---|---|---|---|
| PUBLIC | yes | yes | yes | yes | yes | yes | Identical approved projection; ignore identity |
| ANONYMOUS | yes | yes | yes | yes | yes | yes | CSRF for writes; identity transitions below |
| ACCOUNT | no | yes | yes | yes | yes | yes | Own account/security/export only; not durable learning writes |
| ACCOUNT_RECENT | no | yes | yes | yes | yes | yes | Own account, password ≤5min; privileged account also WebAuthn ≤5min |
| ACCOUNT_ENROLLMENT | no | no | conditional | conditional | conditional | conditional | Recent password, server-issued pending privileged ceremony for first two keys; afterward recent existing MFA |
| ACCOUNT_RECENT_MFA | no | no | conditional | conditional | conditional | conditional | Own credentials, both factors ≤5min; deny removal below two active keys while privileged |
| OWNER | no | no | own only | own only | own only | own only | ACTIVE verified, principal-derived owner; every FK target same owner |
| EDITORIAL | no | no | no | yes | yes | no | EDITOR or REVIEWER_PUBLISHER, both factors, active session; editorial objects only |
| EDITOR_RECENT | no | no | no | yes | no | no | EDITOR and both factors ≤5min |
| PUBLISHER_RECENT | no | no | no | no | yes | no | REVIEWER_PUBLISHER and both factors ≤5min |
| ADMIN_RECENT | no | no | no | no | no | yes | ADMIN and both factors ≤5min; identity/role metadata only |

For role cells, an editor who is also a learner may use OWNER for their own data; one role never grants another role's endpoints. A privileged password-only login returns MFA_REQUIRED with no privileged access until a same-principal WebAuthn assertion succeeds. Assertion-only sessions cannot satisfy password requirements. GET/PUT `/admin/accounts/{accountId}/status` exposes status/version only and permits audited suspension/restoration of an already verified account, revoking all sessions; it cannot verify UNVERIFIED, reopen DELETING or restore revoked roles. Role grant creates pending enrollment where necessary; activation requires two separately recoverable authenticators and target account verification. Grant/revoke requires current RoleState ETag; account generation changes and all sessions revoke. Final administrator removal or weakening the only recovery operator is 409 until the offline operator ceremony covers continuity. No public first-admin, email-to-MFA bypass or support impersonation endpoint.

The principal, not a request/body/URL owner field, scopes list, detail, mutation, count, export, nested answers and remediation. Foreign UUID and absent UUID both yield 404. Admin maintenance sees volunteered issue text, content IDs, queue state and pseudonymous audit actors only; no notes, saved answers, learner email/profile, scores or attempt browsing. Assessment replacement acts on the maintenance request without opening the learner's failed attempt. Suspended/deleting accounts have sessions revoked. Suspended privacy requests use the P03 audited operator procedure outside routine REST roles; no weak password-only privacy bypass. Deletion acknowledgment is the final authenticated response; its minimal receipt is retained by the user, not exposed on a public status endpoint.

Session cookie is `__Host-OTRSESSION; Secure; HttpOnly; SameSite=Lax; Path=/`, no Domain. Spring Security + JDBC Spring Session is sole identity authority. Learner idle/absolute limits are 24h/7d; privileged 15min/8h; pre-auth CSRF 15min idle. Rotate after login/elevation; generation checked on every request and inside sensitive write transactions. Reauthentication does not extend original absolute expiry. Reset/password change/email replacement revoke all sessions; verification marks the account verified and rotates/refreshes any same-account session, never automatically logs in an anonymous token holder. Logout is CSRF-protected and clears cookie; logout-all also revokes every account session.

GET `/auth/session` does not allocate a pre-session when none exists; anonymous account/factor/expiry values are null and roles empty. GET `/auth/csrf` returns Spring's masked session token; store in memory, send X-CSRF-TOKEN on **every unsafe route**, including signup, login, recovery and anonymous practice. Fetch afresh after login/logout, reauthentication/rotation and expiry. Unsafe requests require configured Origin, or same-origin Referer when Origin absent; reject cross-site Fetch Metadata. No credentialed cross-origin access or wildcard CORS in production/development. Preflight cannot authorize another origin. Email-token GET displays a form only; POST consumes token transactionally. Confirmation pages strip secret URLs after capture, use no-referrer and no remote assets. Tokens last verification 24h/reset 30min, one-use, replacement revokes prior secrets.

WebAuthn adapters use the framework's registration/request options and JSON base64url credential responses bounded in OpenAPI; support no requested client extensions initially, reject nonempty extension output. Challenges are five-minute, single-use, account/session/purpose-bound, exact RP/origin and userVerification required. Enrollment labels are escaped text. Framework ceremony failure is 422 generic VALIDATION_FAILED; factor/recency checks are 403. Security keys/credential public material never enter general profile/export DTOs. Framework version-specific option differences must be reconciled with this contract at P07 integration, not silently passed through as arbitrary JSON.

Public SSR fetches use no identity and no session allocation. Optional private/admin SSR forwards **only** the named session cookie to a fixed internal Spring URL, uses no-store, and relies on Spring for every role/owner check. It may forward trusted normalized origin metadata only for a separately reviewed mutation adapter; R1 browser writes go directly through same-origin `/api/v1`. Never forward arbitrary incoming headers, claimed user/role headers, arbitrary URLs or cookies to external sources. Preserve separate Set-Cookie headers when an authorized identity adapter requires them. Preview is `/admin/preview/{id}/revisions/{revision}`, authenticated at both SSR and Spring, with no bearer share link, no public revision override, noindex/no-store and no sitemap entry. A preview revision need not be published, but every referenced draft is still authorized.

## Assessment, practice and progress workflows

Anyone may inspect approved map/scope/prerequisite/resource/path/project metadata, read published lessons and exercise prompts, and use transient exercises with CSRF. Anonymous practice evaluates an authored exercise revision or requests its solution; it persists no response and never awards mastery. Anonymous quizzes expose description/policy only. Diagnostic execution requires a verified account and enrollment, and an approved diagnosticQuizIds link on that path (it is not one of the 43 required R1 items), produces DIAGNOSTIC evidence/routing only, and cannot satisfy a gate. This is a deliberate P05 clarification of J03; transient exercise practice still satisfies J02.

Enrollment creation pins the exact eligible course revision and publication, with 36 topic + six quiz + one dossier requirements for R1. If that closure is not fully reviewed/available return 409 ENROLLMENT_UNAVAILABLE. Full paths currently fail this guard. An old course remains pinned, including missing/withdrawn required items; the denominator never silently shrinks. Migration preview lists changed/removed/added/equivalent/recheck IDs. Explicit migration with source ETag creates a new enrollment, supersedes the old atomically, and only carries exact/reviewed-equivalent evidence. A public revision may be replaced without rewriting old enrollment history. GET `/me/enrollments/{enrollmentId}/topics/{id}` reads only a requirement in that owner’s frozen enrollment, returning its safe pinned lesson revision with the current eligibility generation; withdrawals still override it. Public routes expose current content only; an owned enrollment may reference historical metadata, but historical dangerous text still cannot be delivered.

Progress is topic revision STARTED/SELF_COMPLETED/REOPENED, separate from score/mastery; referenced revision must be current published lesson or a safely retained version in the owner's enrollment. No client mastery field. Whole-module completion is derived from all pinned required topics; R1 has no mark-module-complete mutation because its modules are partial. Dashboard exposes frozen denominators, gate results, self-review and recheck flags separately. Next-step priority: critical remediation → missing hard prerequisite → next released incomplete lesson → eligible gate/project → completed-course/planned-path summary. Required unpublished work yields BLOCKED; recommended preparation is advice, never a gate failure. Reopening updates the owner state via ETag without deleting evidence.

Start attempt accepts only enrollment, quiz identity/revision and requested mode. Server verifies required prior gates/remediation, selects genuinely unexposed form and records exposure atomically with STARTED before prompt delivery. An existing STARTED attempt resumes; no unseen form can be chosen by the client. Exposure persists on abandon, timeout, account migration or cosmetic version change. Freshness is measured against prior exposure before this attempt. Active attempts are untimed; no cron auto-submission. Saving answers requires If-Match and remains private; it does not produce a score. P04 attempt-answer rows may be mutable only while STARTED; submission seals them transactionally. GET of STARTED returns saved answers but no feedback/keys. Lists contain owner attempts only, with the same redaction/freeze policy as details.

Submit supplies the complete ordered answer set and confirmUnanswered. Each ordinal must appear exactly once for the assigned form, no foreign question IDs; explicit SKIPPED requires confirmUnanswered=true. Choice keys must belong to that item; SINGLE exactly one, MULTI unique nonempty set. Malformed numeric or unit input is 422 and leaves STARTED. Server scores against pinned immutable keys; gate ten equal items, three critical, score≥85 with zero critical errors (therefore at least 9/10). MULTI all-or-nothing; numeric correctness uses `abs(actual−expected) ≤ max(absTolerance, relTolerance*abs(expected))`, inclusive, with reviewed pinned unit conversion. Client cannot supply score, correctness, reference or form. A missing answer scores zero only after confirmation.

After SUBMITTED, owner result returns score, version, critical failures, evidence label and item feedback/expected answer for **only that assigned submitted form**. Before submit result GET is 409 FEEDBACK_NOT_AVAILABLE. ABANDONED never gets gate solutions; exposure remains. No other form or other learner's answer appears in result, errors, SSR, public assets, search or export. For critical withdrawal, STARTED becomes effectively frozen (state remains STARTED, frozen=true), saves/submissions rejected 409 ATTEMPT_FROZEN; saved own answers remain readable, questions are empty. Any withdrawn attempt detail/list also returns questions=[] regardless of terminal state; only own saved answers and safe metadata remain. Already submitted scores remain historical; unsafe explanation/expectedAnswer is withheld by returning empty feedback plus needsRecheck=true. Fresh correction evidence is required, never silent rescoring. Minor approved changes may leave the pinned assessment eligible.

Failed gate feedback returns `remediation` entries with topicId/topicRevision and transferExerciseId/transferExerciseRevision; this supplies every reference required by the next command. Learner reads these and completes the authored changed-input transfer exercise; remediation POST includes topicRevision, the transfer ID/revision and selfExplanation acknowledging what was learned. Service checks required owner practice completion/feedback against the pinned remediation mapping (including numeric correctness where defined); mere user-supplied completion or an unrelated exercise fails. Conceptual explanation remains self-attested, not a new scored gate. Only then may the second fresh form start. Two exposures exhaust the original bank; fresh start returns 409 FRESH_FORMS_EXHAUSTED and the learner may create one open assessment request or run PRACTICE. PRACTICE can show feedback after submission but freshEvidence=false, never completes a gate. Replacements need reviewed genuinely new items/exposure groups; reshuffling/cosmetic reversion cannot manufacture freshness. Operator queue target five business days is a target, not automatic approval.

Verified exercise writes are pinned, conditional and owner-only. Solution POST atomically marks solutionViewed=true; later answer edits cannot clear it. Practice feedback is educational/self-review only and cannot create fresh gate mastery. Anonymous solution access has no account evidence to upgrade. Project draft responses validate fields/types against the pinned R1 dossier; no upload or arbitrary code. Numerical checks are server-side; rubric self-scores have authored bounds and total weight 100. Self-review validates ≥85 and no critical errors acknowledged; invalid result is 422 with actionable fields while remaining DRAFT. Successful result seals one submission, releases that project's reference solution, labels SELF_REVIEW and creates no demonstrated mastery. Another review creates a new draft/submission. DELETE `/me/project-writing/{id}` erases all own text/responses/submission copies and derived self-review evidence for that stable project, immediately; it does not delete content or quizzes.

## Editorial, importer, publication and freshness

Editor prepares a typed revision with base/ETag, ordered links and reason. Identity kind is immutable, containment/prerequisite/successor graphs validated, slug permanently reserved. Proposed retirement is a new draft whose `body.retirement` records successor IDs and reason for review; it becomes public through reviewed manifest activation. The editor requests review; reviewer records technical/pedagogy/assessment/accessibility/rights decisions against exact revision/hash. Server records reviewer and same-author review honestly. An edit creates a new revision and invalidates affected approvals. No generic status field can skip this lifecycle. Approval required types depend on MAP/LESSON/PROTECTED/ARCHIVE and P02 content gates.

A publication GET returns its complete selected entries and expected active pointer/generation for review; BUILDING contentVersion describes a candidate, never an active public release. Publisher stages a **complete** candidate manifest plus expected current publication/generation, then activates with candidate ETag. Activation locks/rechecks current pointer and full closure, approvals, rights, DAGs, exact gate/course/assessment references and current eligibility. Materialize the public search projection and switch publication in one transaction; any failure leaves old release/search intact. A losing publisher returns 409 PUBLICATION_CONFLICT. Rollback selects an old reviewed manifest into a new event and validates current constraints; it never rolls back accounts, progress, keys or safety exclusions. Withdrawal increments generation immediately and overrides every manifest/search/navigation/sitemap path. Reinstatement requires a fresh review of the correction, not reuse of the withdrawn body's old approval.

Import uses protected application/zip request, bounded P04 manifest with package ID, schema, source hashes, base release and per-entity revision. Validate/stage is asynchronous; job state VALIDATING then REJECTED/CONFLICTED/STAGED. Report pagination includes safe pointer/code/ID/base/current diagnostics; full report maximum 2 MiB, no learner text. Authorized diff accesses proposals by revision. Revalidation creates the next run number. Applying STAGED proposals checks bases again under locks and updates all draft heads or none; no import publishes. Same manifest replay returns original applied run; different bytes under same package ID gives 409 PACKAGE_ID_REUSED. Missing objects are not retirements. Legacy missing bases may compare only; bootstrap null bases permitted only on an empty catalog. Do not fetch resource URLs during import. Export jobs produce deterministic versioned public allowlists or restricted editorial packages; never learner records in editorial exports. Failed repository/export output does not undo committed database work. The local importer CLI and admin API call the same validation/content service, actor policy, receipts and audit mechanisms; CLI does not bypass role/publication gates.

Resource DTO separates linkCheckedAt/linkStatus from substantiveVerifiedOn/verificationScope/reviewDueAt. Link failure is not proof of false content; HTTP success is not a substantive review. Exact sections and rights/access limitations survive mapping. Required links due 30 days; stable substantive review 180 days. Operational rule eligibility additionally checks source/effective interval, jurisdiction/instrument, active certification and request instant < reviewDueAt (India seven days, others 30). Null actual effective end stays unknown; certification bounds do not invent source expiry. All P01 current operational eligibility remains false. `/admin/rules/{id}/verifications` is a publisher command requiring reviewed source notices and bounded interval; it preserves raw history and increments public generation when eligibility changes. Due queues are operational reminders; request-time checks enforce expiration even if workers stop.

All R1 dynamic API responses (public, auth, private, preview, errors, ZIP downloads) send Cache-Control: no-store. Public responses are identity-independent and set no session cookie. Private/preview additionally send `Vary: Cookie` and `X-Robots-Tag: noindex, nofollow`; authenticated downloads have Content-Disposition attachment with a fixed sanitized filename, no public storage URL. No shared CDN/Next route/data cache, service-worker API cache or 304 response for these endpoints. ETags here are concurrency tokens, not permission to cache. Immutable licensed content-hashed static assets may use public max-age=31536000, immutable; they contain no private content/keys.

Every successful public response includes X-Content-Version `publicationId:generation`, and catalog/search DTOs include matching contentVersion. Multi-query response uses one consistent manifest then rechecks live generation/withdrawal and due-rule eligibility at send time; retry once if changed, then 503 TEMPORARILY_UNAVAILABLE. Dynamic freshness uses request instant, even without generation change. Clients call `/content-version` on navigation/focus and every 30 seconds while visible; on change clear public memory state, restart pagination and refetch affected pages. Every visible-page 30-second check also revalidates the displayed page for date-based eligibility, even if generation is unchanged, so stopped due-queue jobs cannot leave an expired current-rule claim visible. At ≤60 seconds visible clients show corrections; already downloaded content cannot be recalled. Background tabs revalidate on focus before showing actionable stale material. Publication outbox is for secondary exports/audit, never required to hide a withdrawn lesson. Failed containment disables affected routes through maintenance/503. P20 must verify measured latency and freshness; this design is not runtime evidence.

Owner exports are accepted jobs with ≤24h readiness target, authenticated owner-only download expiring 24h after ready; EXPIRED returns 409 EXPORT_NOT_READY with a safe message and new-request action. Export includes owned writing, progress, pinned historical results and permitted submitted-form feedback, never secrets/credentials/unattempted keys or withdrawn unsafe explanations. Account deletion requires recent identity factors and explicit confirmation, immediately revokes/hides, erases live data ≤7d and encrypted backup copies ≤35d, preserving minimal 90-day receipt/erasure journal. Same-account note/dossier erasure journals protect against restore resurrection. Delivery/storage failures remain FAILED jobs, never fictitious successful export/deletion. P19/P21 verify actual retention and restore.

## Standards and implementation gates

Documented wire structure follows [OpenAPI 3.1.1](https://spec.openapis.org/oas/v3.1.1.html). Conditional requests and statuses use [HTTP semantics RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html); safe problem representations use [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html) with this project's extensions. These official sources were inspected on 23 September 2026; they establish protocol meaning, not successful application behavior. This specification chooses 3.1.1 deliberately, without claiming it is the newest specification or that P07's generator is already compatible.

P05 checks schemas/references/examples, the exhaustive authorization inventory, rejection fixtures and J01–J17 contract coverage. P07 proves framework/client/OpenAPI integration; P09 import; P10 public contracts; P13 identity; P14 learner saves; P15 assessments; P16 editorial; P18–P21 real-stack security/load/privacy/recovery. No skipped application test counts as a pass. P05 was the design gate; see the P10 implementation boundary below. Do not start later stages or publish content automatically.

## P10 implemented public boundary

The 23 public content operations above run through closed DTOs, a public service and explicit PostgreSQL projections. The service has no principal-dependent branch, and every successful read is tied to an activated, approved manifest. There is no public entity serialization, draft/preview switch, arbitrary expansion, unpublished title lookup or generic CRUD. Protected quiz/exercise revisions have a MAP **description projection** only: question/form/answer bodies are never selected. Practice, attempts, enrollment and self-review remain unavailable until their respective later implementations.

P09's complete canonical import is still unpublished in the persistent local database. It correctly returns 503 with Retry-After before a publication exists. The integration suite imports the same package into disposable PostgreSQL and explicitly constructs test-only approvals/publications; these fixtures are not a release review or a seed command for the local application. [Actual captured responses and query evidence](evidence/p10/REVIEW.md) distinguish those environments.

V0021 builds weighted English full-text documents and exact membership filters atomically on activation, using the existing GIN index. No external search service is introduced. SQL binds every query/filter value; sorting selects fixed expressions. Title keys use PostgreSQL 18 NFC normalization and Unicode casefold with binary ordering. Assignment status maps canonical `assignment_candidate` to CANDIDATE and `selected_reading` to REVIEWED, preserving the bounded reading scope. Exercise transfer subtypes use the public practical classification. A topic's exercises come only from explicit lesson_practice links. Project topic/path filters use explicit project_topic/path_project or required course-project links; prerequisites and optional branches never create membership.

Public route snapshots freeze the canonical path at first activation of each manifest. Importing a draft slug does not rename a public page. A later approved publication makes old approved paths resolve as RENAMED. Stable kind/semantic-ID fallback paths remain resolvable aliases. Never-public reserved slugs return 404. Withdrawals and retirement override projections and invalidate generations/cursors immediately; unavailable references retain only previously approved identity/title, while never-public relationships disappear.

Optional `ruleNotices` on cards/details/search hits exposes approved dependency IDs, a bounded review deadline, status and computed current-operational eligibility. It contains no rule values. Eligibility uses the recorded market zone and finite certification window; expired/revoked, withdrawn, superseded and unknown evidence cannot become a current claim. Resource link transport and substantive review stay separate. P09 does not create operational certifications. Reads use a repeatable database snapshot, check the live generation after assembly, and restart once if the publication or a known timed safety boundary changes. Dynamic API responses remain no-store, including failures and authenticated/preview requests; If-None-Match never turns these into 304s.

OpenAPI 1.0.2 fixes ID-only patterns on descriptive difficulty/priority/resourceType/tag values, adds optional rule metadata and records implemented operations. It preserves API `/v1`, content schema `1.0.0` and canonical interchange `1.0.0-design`. [Frontend DTO types](../../frontend/src/api/schema.d.ts) regenerate from the normative OpenAPI; `scripts/check-implemented-api.py` checks actual route/DTO exposure, and `scripts/check-public-api.py` validates real HTTP captures against the normative response schemas. Runtime schema output is available only in local/test environments.

Reproduce with `./backend/mvnw -f backend/pom.xml -B verify`, then `python scripts/check-implemented-api.py` and `python scripts/check-public-api.py` in the documented Python environment. Search latency under concurrent load, identity source-rate budgets, lesson authoring/review, publication/editor HTTP controls and production readiness remain their assigned later gates.

## P12 discovery projection — OpenAPI 1.0.4

The browser uses `/search` for all queryable discovery surfaces, setting fixed `kind` values for resource/path/project catalogs. This intentionally uses P10's bounded 0–99 pages and generation token, so filtered URLs survive reload/back navigation; it does not emulate offset pages over keyset list endpoints. Different filters intersect and repeated values within a filter are alternatives. Filter changes reset page/generation; stale generations offer an explicit restart. Facet counts are for the current matching set, with a separate publication-coherent options response preserving zero-count choices. Facet arrays are bounded to 100; exact topic IDs may also be entered.

Optional `DiscoveryFacets.kind/phase/topic/path` arrays expose already-supported public filters. `SearchHit` adds resource author/type/cost/rationale/review metadata in the same bounded query, avoiding a resource-detail request per row. `Resource.prerequisitesText`, path branches/exit statements/milestones and project steps/limitations/noncoding route expose safe sections already imported by P09. Project `assessmentCriteria` now projects rubric **codes and weights**, correcting the earlier repeated objective; rubric descriptions, reference behavior, failures/solutions and answer keys remain private. No mutation, migration, new dependency or public rating contract is introduced. Java DTOs and frontend types are regenerated from this version.
