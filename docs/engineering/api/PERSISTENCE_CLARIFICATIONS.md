# P05 persistence clarifications for P08

These are small additions to the [P04 design](../DATABASE.md) required by the wire workflows, not implemented migrations. Canonical schema/mappings and learner ownership remain unchanged. P08 must include them in its dictionary/ERD/migration tests before implementing the corresponding APIs.

1. **Durable command receipts.** P04 already has attempt request keys, immutable submission hashes, unique active enrollment/open requests and import hashes. Extend the P08 identity/learning/editorial migrations with `command_receipt`: internal identity PK; actor_account_id FK account ON DELETE CASCADE; operation_id varchar(100); route_key varchar(500) (normalized route plus semantic target IDs, never raw query text); request_key UUID; request_sha256 char(64); response_status smallint; created_at/expiry_at timestamptz (24h). Unique `(actor_account_id, operation_id, route_key, request_key)`. Typed nullable result FKs refer to account, enrollment, quiz_attempt, remediation_record, assessment_request, project_work, content_issue, privacy_request, import_batch, catalog_revision, review_decision, publication, content_withdrawal or job. An operation-specific CHECK matrix selects its result kind; no arbitrary table-name/JSON pointer or raw response body. Receipt references to erasable owned rows use ON DELETE CASCADE; account erasure removes actor receipts. Account deletion's acceptance receipt is in privacy_request after revocation, not a public receipt API. Insert receipt with domain commit; deduplicate under lock. In-flight uncommitted receipt cannot report success. Expiry deletes receipts, never durable domain uniqueness/exposure/history. Server-authorized retry reconstructs current safe representation of the original result identity; immutable submitted scores stay identical, mutable workflow status may have advanced. No cached solution can outlive withdrawal. P08 must test two simultaneous same-key requests, reused-key/different-body, stale precondition replay, response loss, expiry and erasure.
2. **Draft answers.** P04 attempt_answer/answer_choice hold optional autosaves while quiz_attempt.state=STARTED. In this state awarded_score/critical_error/feedback are null; replace the owned complete draft set under account/attempt lock and ETag. Empty STARTED responses are valid. Submission validates completeness/explicit skips, finalizes all fields/results atomically and makes answer rows immutable. ABANDONED preserves prior answers/exposure, forbids edits and never returns solutions. No extra shadow answer table or raw JSON bag is needed. The P04 freeze overlay takes precedence over writes and historical question/feedback delivery.
3. **Remediation mapping.** A course gate's protected reviewed sections/typed relations must explicitly map each failed critical/item class to topic revision and a changed-input transfer exercise revision. P08 needs typed `quiz_remediation_requirement(quiz_revision_id FK quiz_revision, question_revision_id FK question_revision, topic_revision_id FK catalog_revision TOPIC, exercise_revision_id FK exercise_revision)` with composite PK and deferred question/form membership validation. No inferred mapping from resource inheritance or client-supplied topic ID. A remediation_record additionally references the satisfying owner practice_response; same-owner composite FK and pinned exercise version checks prevent using another learner's transfer task. Delete practice text by setting this evidence link null while preserving completed remediation time, unless a critical correction explicitly requires recheck; past transfer completion is historical, not a new gate score. Add `practice_response` unique `(id,account_id)` for this FK and ON DELETE SET NULL of only the practice reference. Existing completed explanation may be erased with account deletion as P04 specifies.

Typed authored definitions in OpenAPI are editing DTOs mapped to P04 revision details/sections/links, plus the mapping above. They never become an all-purpose database JSON column. Optional `diagnosticQuizIds` use a constrained PATH→QUIZ `path_diagnostic_quiz` relation in the catalog_link allowlist; require DIAGNOSTIC purpose, and do not add them to the 43 required course items. Course membership expands into path_topic_prerequisite/course_gate/course_project and frozen enrollment requirements. Restricted exercise reference text and project numeric keys never enter public sections. Client-supplied exposure groups are editorial proposals only; the publisher validates substantially new items before any form is eligible as fresh evidence. No runtime implementation or migration readiness is claimed by these clarifications.
