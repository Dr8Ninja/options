# Dependency and package policy

P03 ADR-001 remains the platform decision; [ADR-007](adr/007-foundation-compatibility.md) records executed compatibility amendments. Exact direct versions live in `backend/pom.xml` and `frontend/package.json`; npm's transitive closure and integrity hashes are committed in `package-lock.json`. Use `npm ci`, never force or legacy-peer-deps. All direct npm versions are exact, Node/npm engines are enforced, and generated API types/tokens must match their source files.

Java uses the Boot **4.1.1** BOM, release **25**, managed Framework/Security/Session/Hibernate/Jackson/JUnit/Testcontainers and Maven Wrapper **3.9.16** with its distribution SHA-256. Managed runtime overrides are Tomcat **11.0.26** and the Jackson 2/3 BOMs **2.21.7/3.1.7**, addressing security findings in Boot's older patches. Remove the override when Boot catches up. springdoc **3.1.1** is API-only. No H2, Spring Data REST, snapshot dependencies, independent frontend identity store or unreviewed repository is allowed. Maven resolves from Central; npm resolves from the official registry with SHA-512 lock integrity. Digest-pinned base images and security-tool checksums are in infrastructure/evidence.

Before adding a dependency, document its concrete responsibility, maintenance/advisory status, license, data exposure and why existing dependencies are insufficient. Application packages contain no bundled canonical/private assessment records. Frontend is presentation/API adaptation only; business rules/ownership/transactions remain Spring responsibilities. JPA entities must not become wire DTOs. Cross-module service APIs must be deliberate, and repository access cannot cross controller/flow boundaries.

Updates require review, the contract/type regeneration check, appropriate unit/integration/browser checks and fresh vulnerability scans. Per the user’s 1 October 2026 instruction in AGENTS.md, validated updates are committed and pushed directly to main without creating feature branches or pull requests. Critical/high findings block release until patched or a narrowly scoped, evidence-backed exception is explicitly reviewed; P07 suppresses none. Scan outages remain failed gates. Review support horizons monthly, and begin upgrades 90 days before EOL. Do not use an obsolete compiler/plugin merely to suppress warnings: record and test a compatible supported combination.

Java CycloneDX generation records runtime dependency licenses/hashes in `backend/target/classes/META-INF/sbom/application.cdx.json`; `npm sbom --sbom-format cyclonedx` produces the frontend inventory. The source repository does not invent a redistribution license for supplied archives. Preserve third-party notices, including the Apache-2.0 Maven Wrapper and Spring Session schema attribution.

Security references checked for P07 include [Spring advisories](https://spring.io/security/), [WebAuthn session-verification fix](https://spring.io/security/cve-2026-47841/), [Tomcat 11 advisories](https://tomcat.apache.org/security-11.html), [Next security updates](https://nextjs.org/blog), and official package metadata. Spring Security 7.1.1 fixes the documented distributed-session user-verification issue; the isolated virtual-authenticator probe checks the selected framework behavior. This does not establish complete account security or replace P19.

P08 adds `org.bouncycastle:bcprov-jdk18on:1.86` (MIT license), the local cryptographic provider required by Spring Security's Argon2 password encoder. Boot does not manage its version. It performs no network/data transfer; only password hashing uses it. Version 1.86 was checked against [Bouncy Castle Java releases](https://www.bouncycastle.org/download/bouncy-castle-java/) and Maven Central metadata on 25 September 2026, and the resolved SBOM passes the recorded HIGH/CRITICAL scan. Use Spring's encoder rather than application cryptography. This explicit pin must be included in dependency updates and scans.


P09's operator-only Python CLI uses Psycopg **3.3.6** (LGPL-3.0-only) for parameter-bound PostgreSQL operations and the existing JSON Schema **4.26.0** validator. Ruff **0.16.9** is a development formatter/linter. These packages are not web application dependencies and perform no URL fetching during import. [The operator requirements](../../scripts/requirements-content-import.txt) pin the complete resolved closure and PyPI release SHA-256 hashes for supported wheels; install with `--require-hashes`. Psycopg's [transaction documentation](https://www.psycopg.org/psycopg3/docs/basic/transactions.html) informed the explicit transaction/read-only boundaries. Version/license metadata and hashes were checked against the official [Psycopg release metadata](https://pypi.org/pypi/psycopg/3.3.6/json) and [Ruff release metadata](https://pypi.org/pypi/ruff/0.16.9/json). The dedicated importer login has no learner-reading/writing or publication activation privileges. Operator dependencies receive the same advisory scan policy as the application.

## P11 restricted authored-content renderer

P11 adds exact pins `react-markdown` 10.1.0, `remark-gfm` 4.0.1, `remark-math` 6.0.0, `rehype-sanitize` 6.0.0, `rehype-katex` 7.0.1 and `katex` 0.18.9 (MIT licenses). Existing React/Next cannot parse and safely render the authored format selected in ADR-005. These packages perform server-side Markdown/GFM/math transformation; they do not fetch content, execute lesson code or transmit data. KaTeX CSS/fonts are packaged locally; no CDN or remote-font request is introduced. Exact npm registry metadata, lock integrity, current audit output, component checks and production build are verified in the P11 gate.

The [react-markdown security guidance](https://github.com/remarkjs/react-markdown#security), [rehype-sanitize math ordering example](https://github.com/rehypejs/rehype-sanitize#example-math) and [KaTeX options](https://katex.org/docs/options.html) informed the fixed plugin sequence: parse with no raw HTML, sanitize, then trusted KaTeX HTML+MathML with `trust: false`, finite macro/size/input bounds. No MDX or arbitrary plugins are accepted. Images without a reviewed local asset are represented by their alternative text; remote images are not fetched. The renderer remains a server component, with a small client-only copy-code action. Advisory monitoring and P19 security review still apply to this expanded dependency closure.

## P13 mail and Jackson security patches

Adds Boot-managed `spring-boot-starter-mail` for the local sink and configured authenticated SMTP transport; no independent mail SDK is added. Runtime licenses/dependencies are captured in the resolved CycloneDX SBOM. The pinned SecLists 10k common-password file is reduced to local SHA-256 values; its MIT notice is retained under `backend/src/main/resources/identity/SECLISTS-LICENSE.txt` and source fingerprint under `evidence/p13/password-blocklist.json`. Passwords never leave the service for a breach lookup.

The previous hosted CI's Jackson HIGH findings require 2.21.7/3.1.7 maintenance-line overrides. The [FasterXML advisory](https://github.com/FasterXML/jackson-databind/security/advisories/GHSA-cxp5-3px4-pw24) confirms these patched versions. Official [Spring passkey documentation](https://docs.spring.io/spring-security/reference/servlet/authentication/passkeys.html) and [password encoder documentation](https://docs.spring.io/spring-security/reference/servlet/authentication/passwords/password-encoder.html) were checked on 3 October 2026 alongside the actual 7.1.1 library contracts. Remove overrides when Boot supplies equivalent or newer fixes. P13's scan results are recorded separately; existing OS-image findings remain release blockers.

On 3 October the full npm audit reports four HIGH affected package nodes (`braces` → `micromatch` → `fast-glob` → the Next ESLint plugin), representing **one underlying advisory**, [CVE-2026-93687](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm). The registry's latest braces is still 3.0.3 and the advisory has no patched release. The latest Next lint plugin 16.3.8 still depends on the affected chain. Do not accept npm's proposed downgrade to Next 14 tooling or remove lint rules to make a check green. Production `npm audit --omit=dev` reports zero findings; these dependencies are build-time tooling driven by repository/configuration patterns, not the account HTTP input path. The full npm audit/CI gate remains red, with no waiver or suppressed finding. Recheck the upstream fix before closing the project security gate.
