## Direction and content truth

“Options / A field guide to learning” is a provisional descriptive wordmark, not a purchased brand or an assumed user preference. U06 remains open. The visual language is a quiet field guide: warm neutral paper, dark green-black ink, restrained teal actions, a serif editorial voice and clear sans-serif interface labels. Thin rules and structured lists organize the curriculum. Large rounded dashboards, trading-terminal neon, decorative market candles, gradient heroes, gamified streaks and profit statistics have no role here.

Reading leads the hierarchy. One dominant action per task, generous prose width, useful whitespace and exact labels distinguish what can be learned now from what remains planned. A gentle filled surface highlights the next step; not every content item needs a card. Resource results and topic sequences are rows, so long titles, dates and review limits remain comparable. The prototype uses no third-party images/fonts or external scripts, and is wholly separate from application code.

State vocabulary is not interchangeable:

| Product label | Meaning | Available action |
|---|---|---|
| Planned scope | Approved public outline; no completed teaching claimed | Inspect scope, preparation and related paths; never Start lesson / Complete / Quiz |
| Published lesson | Exact reviewed teaching and practice is publicly available | Read without signing in; practice transiently; sign in only for durable records |
| In review | An editorial workflow label | Editor-only status; do not reveal a never-public draft through public readiness |
| Self-completed | Learner marked that exact topic revision complete | Reopen deliberately; never a mastery badge |
| Gate passed | Fresh reviewed form meets score and all critical checks | Show scoped outcome and earned version; no whole-module inference |
| Self-reviewed project | Structured dossier met self-review conditions | Explicitly distinct from independent grading or demonstrated mastery |
| Needs recheck | Critical correction affects prior evidence | Preserve original score/version; link to safe remediation |
| Withdrawn / retired | Delivery is restricted or identity superseded | Safe explanation/replacement; keep frozen course requirement/history |

Home currently says Explore Foundations / Course in preparation. After the **complete** R1 course is eligible, the primary becomes Start Foundations and links to its course overview; then F01 is a second activation away. A returning enrolled learner sees Resume Foundations after identity is resolved. Public SSR must never invent a logged-in state. Published/planned counts come from approved catalog data, not a marketing constant. Initial source-only map examples are labeled as design records; metadata still needs the publication/rights gate.

## Responsive layouts

The exact [tokens](../../design/tokens.json) define color pairs, fonts, sizing and spacing. Page max width 1,248px; outer padding 40px desktop, 24px intermediate, 20px narrow; text max 66ch. Paragraphs never stretch across the entire desktop. Desktop editorial reading uses a 200–232px outline rail, 48–64px gap and 66ch article. A secondary action rail is only for shorter catalog/detail layouts, never squeezes the lesson to four words per line.

Breakpoints are content-driven at 640/960/1200 CSS pixels; validation widths are 320, 390, 768, 1280 and 1440. At <960 primary links collapse into a Menu disclosure, leaving the wordmark/account utility visible. Its DOM order remains before main content; it does not trap focus. At <640 all two/three-column panels stack; row metadata wraps; button groups wrap without changing visual versus reading order. No sticky bottom bar covers content or keyboard focus. Desktop lesson outline becomes a native “In this lesson” disclosure before article text. Breadcrumbs wrap, never ellipsize the only identity context. Font zoom must trigger overflow-safe wrapping independently of viewport media queries.

The roadmap is an ordered list of phase disclosures at all widths. Expanded phases contain module rows; prerequisite details use three explicitly titled lists: Required for assessment, Recommended, Optional. A future diagram can supplement but never replace that list; dragging, hovering, color or a wide canvas cannot be the only way to discover an edge. P06 deliberately selects the list as the primary mobile and desktop map.

Resource library uses a horizontal search row, visible applied filters and an expandable Refine group. On desktop, facet controls fit three columns; on mobile, they stack in one disclosure. Do not open a modal filter drawer merely to gain a few pixels. Results remain a linear list with title, source/type, rationale, priority/difficulty/access, estimate, reviewed scope/date and inspect action. Long labels wrap or reside in an adequately sized native select; never truncate the only selected filter label. P05 exact range labels stay intact. Public list page sizes are 20/50 with previous/next controls; search uses bounded pages, other lists maintain an in-memory cursor stack. URL encodes allowed query state; changing filters resets page/cursor and generation.

Dense essential ledgers remain semantic tables in an explicitly labeled, focusable horizontal scroll region. Ordinary two-column comparison tables fit mobile without scroll. Never shrink table text below 15px to force fit. On <640, the sample chart becomes its **open equivalent data table**, preventing unreadable axis labels. At wider sizes, chart title, axis quantities/units, short text summary and equivalent data disclosure remain. Missing/unknown numeric data never draws a zero line. Print exposes lesson/citations/tables, omits app chrome and personal notes by default.

## Screen composition and critical workflows

Home: one editorial statement, limited outcome paragraph, primary Foundation action/secondary map action; adjacent course preview; count strip with explicit design/readiness labels; three path starting points; learning method; selected project specs; source/education footer. No invented returns/testimonials or professional certification promise. Learn: exact release identity/estimate, lesson sequence grouped into six batches, gate boundaries and dossier, explanation of enrollment readiness. Full canonical paths are different pages and explicitly incomplete.

Module: breadcrumb/ID/title/why, full-module effort basis, objectives, readiness notice, ordered topic scopes, common mistakes and prerequisite/resource rail. Topic: same identity/breadcrumb; an outline is a useful page with independent scope units, no empty reading controls. Published lesson: outcome, preparation, title/time basis, original explanation, defined symbols, worked example, misconception, practice/feedback, exact reading scope/citations, completion/bookmark/note controls, safe next step. The prototype's M01.01 original snippet is a **layout sample only**, not P17 authoring or review.

Path: audience, entry criteria, exit goals, ordered shared modules/branches, effort estimate and readiness explanation; no enroll action for a map-only full path. Project/capstone: goal, required skills, deliverables, lawful data plan, steps, limitations, broad assessment criteria and effort. PR01–PR12/capstones never show a fake upload workspace. The R1-CASE-01 manual dossier has a separate structured draft/self-review layout and self-assessment label.

Identity: a focused form panel and a quiet explanation panel; small mobile layout puts the form first. Persistent visible labels, password manager/autocomplete support, paste enabled, Show/Hide password state, explicit error association, generic account-existence responses. Link consumption is an explicit confirmation form, not an email GET. Verification pending allows reading, blocks durable learning saves with a clear verify/resend route. Expired/replaced token gives one safe “This link is no longer valid; request the latest message” state. A delivery outage never claims a message arrived. A privileged login requires password plus registered key; pending enrollment needs two independently recoverable authenticators, with recovery policy visible. Actual WebAuthn ceremony is implemented and tested later.

Dashboard: frozen course name/version, lesson self-completion numerator/denominator, gate evidence and dossier outcome in **three separate measures**; explained next step; recent saved places; correction/migration notice. Do not compute one “mastery percentage”. Recommendation priority remains remediation → required prerequisite → next released incomplete lesson → eligible gate/project → course-complete/next planned path. No eligible item says why. A version comparison lists added/changed/retired/approved-equivalent IDs and asks for deliberate migration; 18/36 stays 18/36 until then. Bookmarks list stable references/tombstones; notes show plain-text editor, character allowance, saved/unsaved state and explicit conflict comparison.

Assessment: course/gate/version context, untimed policy, question/fieldset label, critical marker without key, optional progress through ten questions, Save answers and Review & submit. SINGLE uses radios, MULTI checkboxes, numerical uses text with decimal input mode and visible units/rounding. No answer indication before final submit. Confirmation lists unanswered items and requires explicit acknowledgment. Submission locks answers; owner result shows scoped score, critical overrides, permitted item feedback and exact remediation/transfer IDs. Freshness and bank exhaustion are explicit: request replacement or labeled repeated practice, never cosmetic reshuffle as new evidence. Withdrawal freezes writes and removes unsafe prompts/feedback while preserving own answers/historical score.

Dossier: contract inputs, signed ledger, assignment/reconciliation, rubric self-review; step navigation never discards current draft. Save confirmation only after server acknowledgment. Sum of text inputs ≤20,000 characters; field-level and form-wide errors. Final review repeats the evidence label, critical acknowledgment and irreversible sealing; failed numeric/rubric check retains draft. Successful result releases its own reference and says Self-reviewed project. No file picker/code executor. Delete writing explains that all own versions/submission copies and derived self-review evidence are removed.

Editorial: separate navigation, role/factor indicator, review queue, typed metadata plus restricted Markdown source, authenticated preview, exact revision/base, and required review dimensions. On narrow screens, source precedes preview with anchor links rather than unreadable split panes. Reordering includes Move up/Move down buttons and ordinal text; optional drag enhancement never the only control. Diff labels Base / Current / Proposed, preserves unsaved text, and creates a new reviewed revision after resolution. Import is a bounded package workflow: select → validate/stage → inspect report → resolve conflicts → apply drafts. Apply is disabled with the precise reason while conflicted; there is no auto-publish checkbox.

Publication: full selected manifest, same-author attribution, exact review hashes and public impact → recent-auth check → deliberate activation. Block missing reviews/rights/closure with linked affected IDs. A stale expected release opens a refresh/review conflict, not a force-save button. Withdrawal: content IDs, safe public reason, impact/evidence recheck notice and deliberate confirmation; rollback: target coherent release, exclusions surviving rollback, unchanged learner data and new event. Admin access screen lists account public identity/status/roles only; suspended→active cannot reopen DELETING or restore revoked roles. No staff browsing of learners' notes, email bodies or attempts.

## State and interaction architecture

The [state specification](../../design/specs/INTERACTIONS.md) provides default/loading/empty/error/success/interrupted treatment per J01–J17 and sensitive workflow. Use an accessible loading message by 500ms; at 10s keep rendered public content and offer retry. Do not animate skeleton shimmer. Empty is calm explanatory copy with a useful action; no red error styling. Local validation links to associated fields. Network/auth/version/rate failures cannot claim Saved. Unsaved data stays in the current tab only; no service worker, localStorage/IndexedDB note cache or background mutation queue.

401 → hide private content and show sign-in recovery with safe same-origin return; 403 CSRF → fetch a fresh token and ask for deliberate retry; missing privilege → explain required capability without revealing object details; foreign-owner 404 → neutral unavailable. 412 → show current/unsaved comparison and retain draft. 409 content-generation → restart discovery safely; course denominator stays frozen. 409 attempt-frozen → safe correction notice; no retry of unsafe submission. 429 → visible Retry-After countdown or text, no automatic retry loop; 503 → retry only after stated interval. Unknown technical code still uses a safe message plus correlation reference; never raw backend text/SQL. Explicit logout/account switch clears private memory with a pre-loss copy option.

Dialog uses native modal semantics, labeled heading/description, focus on the heading for long content, inert background, tab containment, Escape cancel where safe and focus return to trigger. Destructive action is explicit and visually separated from Cancel; color alone does not identify it. Long comparisons use a full page if taller than the viewport, not nested scrolling dialogs. User typing is never discarded because publication polling refreshed a lesson. Toasts are supplementary; persisted result remains inline near the action.

## Rendering, security and technical handoff

P07 follows Next App Router/React/TypeScript, selected in P03; this plain HTML/CSS/JS prototype is **not** a replacement architecture or application scaffold. Build typed route DTO adapters from OpenAPI 1.0.1. Server-render public text, hierarchy and metadata; use small client components for filters, notes, account and assessments. No business mutations in Next Server Actions. Spring remains the sole auth, role, owner, scoring, validation and publication authority. Public fetches omit identity; private SSR forwards only the named session cookie to the configured internal API, never user/role headers or arbitrary URL. Preview and every private response remain no-store/noindex.

R1 dynamic API/HTML has no shared cache/ISR/prefetch. Read-time availability is checked on navigation, foreground focus and every 30 seconds while visible; revalidate displayed date-based eligibility even with unchanged generation. Correction replaces unsafe public material, preserves in-tab private draft, and never silently rewrites earned scores. Fingerprinted public static assets only may cache; no private answers or canonical restricted source content in frontend bundles.

Use restricted Markdown plus reviewed sanitizer and trusted KaTeX HTML+MathML per ADR-005. The prototype's native MathML demonstrates structure, not selected production renderer integration. Each formula defines symbols/units and has verbal reasoning. Render code inertly with copy action; no execution. Local approved images need alt text/caption/dimensions; no remote-image fetching. External links say when a new tab opens and use safe relationship attributes. Print omits notes/answers unless a deliberate separate owner export. Content not published is noindex; only approved indexable pages enter sitemap; search/filter variants canonicalize/noindex according to SEO policy.

No app/font package versions are selected or upgraded in P06. System fonts avoid remote requests and layout shifts; if a licensed self-hosted font is later proposed, it needs rights, fallback and performance/accessibility comparison without changing the typography hierarchy. Preserve P02's 1MiB public initial transfer, 200KiB JS and 150KiB critical style/font budgets. The prototype's combined canonical fixture bundle is not a production fetching strategy.

## P13 account implementation

`/account/sign-in`, `/account/register`, `/account/verify`, `/account/recover`, `/account/reset`, `/account/confirm-email`, `/account/security-key` and protected `/account` use the live identity API. Forms have visible labels, password-manager/autocomplete support, password reveal, native eligibility validation, busy states and safe announced errors. Verification/recovery fragments are removed from history and retained only in memory until an explicit confirmation. No confirmation mutation occurs during server rendering or on link opening. Successful authentication navigates by full document load to an allowlisted destination; external, protocol-relative and arbitrary return URLs fall back to the account page.

Private account SSR forwards only this request's session cookie and is never cached/indexed. Session checks on restoration/visibility and periodic checks detect revocation or another account; outgoing pages hide private content before history restoration until a fresh session check succeeds. Account mutation 401 responses hide the account and return to sign-in. Security-key controls call the browser credential API and the server's framework verification; enrollment never grants privileges. Email delivery and operator custody requirements are stated honestly. No progress, bookmark, dashboard or social-login controls are introduced before their stages.
